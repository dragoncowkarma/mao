> 에이전트 규칙은 `AGENTS.md`가 정하며, 이 폴더와 어긋나면 `AGENTS.md`가 우선합니다.

## 다섯 줄 요약

1. **방향은 맞습니다.** 한 AI가 만든 변경을 다른 벤더의 AI가 검증해야 머지되는 파이프라인은, 플랫폼이 이슈→PR→리뷰를 기본 기능으로 흡수한 뒤에도 남는 차별점입니다.
2. **구현은 아직 그 약속을 지키지 못합니다.** 리뷰어는 제목만 보고, 리뷰는 머지를 막지 못하며, provider가 둘이면 PR을 쓴 쪽이 머지 단계를 맡습니다.
3. **공개 저장소에 쓰기에는 위험합니다.** 누구든 이슈 하나로 권한 확인이 꺼진 에이전트를 실행시킬 수 있고, 그 에이전트는 저장된 토큰에 닿습니다.
4. **최근 두 달의 투자는 핵심에서 벗어났습니다.** 10월에 머지한 PR 11건 중 7건이 `config.json` 손상 방어였고, v0.1.0 이후 커밋 191개가 출시되지 않았습니다.
5. **다음 3개월은 "증거 없이는 머지하지 않는다"를 코드로 만드는 데 쓰기를 제안합니다.** UI 외관 작업과 store 하드닝은 그동안 멈춥니다.

## AI 세션을 위한 안내

- 새 기능의 범위를 정하거나 이슈를 만들기 전에 `roadmap.md`의 단계와 "하지 않을 것"을 확인합니다.
- 로드맵 항목은 `A1`, `B2`, `N4` 같은 id로 부릅니다. 대응 이슈 번호는 `roadmap.md`의 표에 있습니다. 전체를 묶는 추적 이슈는 #138입니다.
- 이슈에 착수하기 전에 전제를 현재 코드에서 다시 확인합니다. 이 문서들은 `ac0915e` 시점의 기록이고, 열린 PR(#107 등)이 머지되면 일부가 달라집니다.
- 외부 제품과 수치는 빠르게 바뀝니다. `benchmarking.md`와 `user-needs.md`는 확인 수준 표기와 함께 읽고, 인용하기 전에 출처를 다시 확인합니다.

## 점검 방법

- **코드 감사.** 다섯 개 전문 렌즈(제품·에이전트 시스템, 보안·GitHub 플랫폼, 아키텍처·신뢰성, UX·DX·문서, QA·릴리스·프로세스)가 저장소를 읽기 전용으로 검토했습니다. 테스트와 앱은 실행하지 않았습니다.
- **외부 리서치.** 네 개 각도(경쟁·인접 제품, 리뷰 거버넌스와 오케스트레이션 패턴, 에이전트 통합과 보안, 이용자와 시장)를 웹에서 조사했습니다.
- **교차 확인.** 감사의 핵심 주장은 코디네이터가 코드에서 다시 읽어 확인했고, 이슈 초안은 작성 단계에서 `origin/main` 기준으로 한 번 더 검증했습니다.

## 갱신

- 분기마다, 또는 단계의 완료 조건을 달성했을 때 `roadmap.md`를 갱신합니다.
- 채택한 결정은 `docs/adr/`에 한 쪽짜리 기록으로 남기기를 제안합니다.
