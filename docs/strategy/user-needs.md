# 잠재 이용자층과 니즈 분석

- 작성일: 2026-11-12
- 이 문서는 요약입니다. 인용, 수치, 출처 URL은 [appendix/research-users-and-market.md](appendix/research-users-and-market.md)에 있습니다.
- **확인 수준.** 리서치가 원문을 직접 연 것은 METR 보고, GitHub 블로그, Stack Overflow 2026 펄스 조사, 일부 제품 페이지와 토론 스레드 한 건입니다. 나머지 수치(JetBrains 2026 조사, 투자·폐업 보도 등)는 검색 요약이나 2차 보도입니다. Reddit과 한국 커뮤니티의 실제 스레드는 확보하지 못했습니다. 인용하기 전에 출처를 다시 확인하십시오.
- 괄호 안의 `A1`, `B2` 등은 [roadmap.md](roadmap.md)의 항목 id입니다.

## 1. 요약

- **가장 가까운 이용자.** AI 구독이나 API 키를 여러 개 가진 1인 개발자, 또는 2~3인 팀입니다. 로컬 실행, 자기 키 사용, 벤더 교차 검증이 이들의 조건과 맞습니다.
- **상위 니즈.**
  1. 한 에이전트가 쓴 것을 다른 쪽이 증거를 보고 검증해 주는 것 (B2, B5)
  2. 무엇이 자동으로 머지되고 무엇이 사람을 기다리는지 정하는 정책 (B3)
  3. CI 실패와 리뷰 지적을 되돌려 고치게 하는 수정 루프 (N1)
  4. 단계별 비용과 한도 가시화 (N3)
  5. 작성자를 가리는 안전한 자동 트리거와 기본 보안 (A1, A2)
- **쫓지 말 것.** 에이전트 수 경쟁, 범용 칸반과 모바일 앱, 검증 능력이 없는 이용자를 위한 원클릭 자동화.

## 2. 시장 맥락

| 관찰 | 근거(확인 수준) |
| --- | --- |
| 에이전트 사용은 보편화됐습니다. | Stack Overflow 2026 펄스: 업무에서 사용 59%, 매일 사용이 14%에서 37%로(원문 확인). JetBrains 2026: 전문 개발자의 90%가 주 1회 이상 사용(검색 요약) |
| 여러 에이전트를 조율하는 사람은 소수입니다. | 단일 에이전트 69%, 전문화된 다중 17%, 조율형 다중 16%(리서치 요약 기준, 원자료 참조) |
| 병목이 생성에서 검토와 신뢰로 옮겨 갔습니다. | METR 2026-03: 벤치마크를 통과한 PR의 절반가량을 메인테이너가 머지하지 않음(원문 확인). 완전 자율을 믿지 않는다는 응답 63%(Stack Overflow 펄스) |
| 플랫폼이 다중 에이전트와 이슈→PR을 흡수하고 있습니다. | GitHub Agent HQ, 벤더들의 리뷰 기능과 교차 리뷰 플러그인(확인 또는 부분 확인) |
| 독립 오케스트레이터는 양극화됐습니다. | 투자를 받은 제품이 있는 반면, 스타가 많던 칸반 오케스트레이터의 운영 회사는 무료 사용자 위주라 지속하지 못하고 종료(부분 확인) |

읽는 법: 이용자층은 "이미 에이전트를 여러 개 쓰는 사람"으로 좁고, 그들이 돈과 시간을 쓰는 곳은 UI가 아니라 검증·거버넌스·보안입니다.

## 3. 페르소나

| 페르소나 | 해결하려는 일 | 반드시 필요한 것 | 탈락 사유 | 지금의 적합도 |
| --- | --- | --- | --- | --- |
| 여러 구독·키를 가진 1인 개발자 | 자리를 비운 사이 이슈를 처리하고, 믿을 만한 결과만 확인하기 | 교차 검증, 한도·비용 가시화, 쉬운 되돌리기, 설치 마찰 없음 | 지켜봐야만 하는 도구, 예측 못 할 비용 | 높음(개념) / 낮음(구현) |
| 소규모 제품 팀 | 리뷰 부담을 줄이면서 품질 유지 | 머지 정책, 필수 CI, 수정 루프, 이력 | 정책 없는 자동 머지 | 낮음 |
| 오픈소스 메인테이너 | 외부 이슈를 안전하게 다루고 저장소 규범을 지키는 PR 받기 | 작성자 게이트, 규범 준수, 사람 승인 기본 | 아무 이슈나 에이전트 입력이 되는 구조 | 낮음, 지금은 위험 |
| 플랫폼·DevEx 팀 | 감사 가능하고 격리된 에이전트 운영 | 샌드박스, 최소 권한 토큰, 서명된 빌드, 감사 로그 | 평문 토큰, 권한 우회 실행 | 낮음 |
| 에이전시·컨설턴트 | 고객 저장소별 격리와 사용량 보고 | 저장소별 자격증명, 비용 보고 | 격리 없음 | 낮음(추정 수요) |
| 비개발자 빌더 | 한 줄 요청에서 동작하는 결과까지 | 설명 가능한 진행 표시 | 검증할 수 없는 자동 머지 | 대상 아님 |

## 4. 니즈 매트릭스

| 니즈 | 주 페르소나 | 지금의 적합도 | 로드맵 |
| --- | --- | --- | --- |
| 다른 공급자가 검증하는 자동 리뷰 | 1인 개발자 | 개념은 맞지만 리뷰어가 diff를 못 봄 | B1, B2, B5 |
| 구독 한도와 비용을 가로지르는 라우팅 | 1인 개발자 | 공급자 지정은 있고, 한도 인지와 자동 전환은 없음 | B7, N3 |
| 사람이 읽기 전에 기계가 거르기 | 1인 개발자, 팀 | CI 게이트만 있고 CI가 없으면 통과 | B3, N2 |
| 지켜보지 않아도 되는 실행 | 1인 개발자 | 알림, 진행 표시, 수정 루프 없음 | N1, N3, N7 |
| 자동 머지 전의 명시적 정책 | 팀 | 단계별 자동 진행 on/off뿐 | B3, L5 |
| CI 실패와 리뷰 지적의 수정 루프 | 팀 | 메인 엔진에 없음, Swarm에 있음 | N1 |
| 외부 이슈를 신뢰 경계로 다루기 | 메인테이너 | 없음 | A1 |
| 저장소 규범을 지키는 PR | 메인테이너 | 프롬프트에 규범이 들어가지 않음 | B1 |
| 감사 가능성 | 플랫폼 팀 | 단계 이력은 있고 토큰과 저장이 약함 | N3, N4, N6 |
| 샌드박스와 최소 권한 | 플랫폼 팀 | 정반대 | A2, N9 |
| 실시간 진행, 알림, 중단 | 전원 | 일시 정지·재시도만 있음 | C3, N3, N7 |
| 비용 예측 | 전원 | 없음 | N3 |
| 설치 마찰 없음 | 1인 개발자, 팀 | 구조는 가볍지만 패키지와 서명 빌드가 없음 | N10, L7 |
| 한국어 설정·문서·사례 | 한국어권 개발자 | UI와 문서는 영어 | E3, L8 |

## 5. 자동 머지를 믿게 만드는 조건

- **1인 개발자:** 쉬운 되돌리기, 증거(diff, 테스트 결과, 다른 공급자의 판정), 비용 상한.
- **소규모 팀:** 필수 CI, 보호 경로 승인, 감사할 수 있는 이력, 실패 시 자동 중단.
- **메인테이너:** 작성자 게이트, 저장소 규범 준수, 사람 승인 기본(자동 머지는 라벨로 옵트인).
- **플랫폼 팀:** 샌드박스, 최소 권한 토큰, 서명된 빌드, 감사 로그.

공통 전제는 단계적 자율성입니다. 제안만 하기 → 승인 뒤 머지 → 조건부 자동 머지 순서로 넓힙니다. (B3)

## 6. 포지셔닝 세 가지 안

| 안 | 대상 | 차별점 | 필요한 증거 | 플랫폼에 흡수될 위험 |
| --- | --- | --- | --- | --- |
| A. 교차 공급자 검증 파이프라인 | 1인·소규모 | maker-checker | 교차 검증이 잡아낸 결함 비율의 비교 실험 | 높음. 벤더도 교차 리뷰 수단을 내놓고 있음 |
| B. 신뢰할 수 있는 머지 | 소규모 팀, 메인테이너 | 정책, 증거, 작성자 게이트, 막을 수 있는 리뷰 | 머지 뒤 회귀와 되돌림 비율 공개 | 중간. 번들 기능은 정책 맞춤과 로컬 키를 주지 못함 |
| C. 로컬 우선 이슈 러너(한국어권) | 한국의 개인·스튜디오 | 한국어 경험과 쉬운 설치 | 사용자 수와 후기 | 낮지만 시장이 작고 방어력이 약함 |

**권고:** B를 중심에 두고, A를 그 안의 작동 원리로, C를 유통 채널로 씁니다. 병목이 검토와 신뢰로 옮겨 갔고, 플랫폼은 단순 오케스트레이션을 흡수하고 있으며, 무료 칸반 UI는 지속되지 못했다는 관찰에 근거합니다.

## 7. 이름, 약관, 채널

- **이름.** "MAO"와 "multi-agent orchestrator"는 같은 이름의 프로젝트가 여럿 있고, 같은 일반 명칭을 쓰던 대형 프로젝트는 이름을 바꿨습니다. 검색에서 찾기 어렵습니다. 사용자가 거의 없는 지금이 이름을 바꾸는 비용이 가장 낮습니다. 후보를 정할 때는 패키지 저장소, GitHub, 도메인, 검색 결과에서 실제로 쓸 수 있는지 확인합니다. 구체적인 후보는 가용성을 확인하지 못해 제시하지 않습니다. 기존 `mao` 명령은 별칭으로 남깁니다.
- **약관.** 구독으로 로그인한 CLI를 무인으로 반복 실행하는 것이 각 벤더 약관에서 허용되는지는 확인하지 못했습니다. API 키 경로를 1급으로 문서화하고, 구독 CLI 경로의 불확실성을 README에 밝히기를 권합니다. 법률 자문이 아닙니다. (E3)
- **채널.** 유지보수자가 한국어 화자이므로 한국어 커뮤니티(GeekNews 등)를 첫 무대로 삼고, 그 뒤 영어권으로 넓힙니다. 가장 설득력 있는 자료는 실제 저장소에서 "이슈 → PR → 교차 리뷰 → 거절과 수정 → 머지"가 진행되는 기록과 측정 결과입니다.

## 8. 쫓지 않을 니즈

에이전트 수십 개의 병렬 실행, 범용 칸반 UI, 모바일·원격 감독 앱, 비개발자를 위한 원클릭 자동 배포, 조직 단위 거버넌스 플랫폼, 구독 인증 우회, 호스팅 서비스. 자금력 있는 제품이나 플랫폼이 이미 차지했거나, 1인 유지보수로 감당하기 어렵거나, 검증 없는 자동화를 부추기기 때문입니다.
